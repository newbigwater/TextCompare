# 부록: 정규식 입문 (제외 필터용)

[[00-개요|← 개요로 돌아가기]]

TextCompare의 **제외 필터**(비교 화면 상단 "제외 필터" 체크박스 + "편집..." 버튼) 기능은 정규식(Regular Expression, 흔히 "정규표현식"이라 부름) 패턴으로 비교에서 무시할 내용을 지정한다. 패턴마다 두 가지 **모드** 중 하나를 고를 수 있다:

- **라인 전체 제외**: 패턴에 일치하는 줄을 비교·화면에서 통째로 제거한다.
- **매치 부분만 제외**: 줄은 화면에 그대로 남고, 패턴에 일치한 구간만 비교에서 무시된다(그 구간은 회색 배경으로 표시). 예를 들어 `address="[^"]*"` 패턴을 이 모드로 등록하면, 좌/우 줄이 address 값만 다를 때 "같음"으로 판정되면서 줄 자체는 계속 보인다.

이 문서는 정규식을 한 번도 써본 적 없는 사람도 제외 필터를 바로 쓸 수 있도록 쓴 입문 자료다.

## 1. 가장 중요한 사실: 몰라도 반은 쓸 수 있다

**특수 기호가 하나도 없는 평범한 글자만 입력해도 정규식으로 동작한다.** 예를 들어 어떤 줄에 `TIMESTAMP`라는 단어가 들어있으면 그 줄을 통째로 제외하고 싶다면, 그냥 패턴 칸에

```
TIMESTAMP
```

라고 입력하면 끝이다. 이건 "TIMESTAMP라는 글자가 줄 어딘가에 있으면 매칭"이라는 뜻이고, 정규식 지식이 전혀 없어도 직관적으로 맞다. **줄의 처음부터 끝까지 정확히 일치해야 하는 게 아니라, 줄 안 어딘가에 포함만 되어 있으면 매칭된다** — 이것만 기억하면 아래 특수 기호들은 "더 정교하게 고르고 싶을 때"만 필요하다.

## 2. 특수 기호가 필요해지는 순간

아래 상황들은 "평범한 글자 입력"만으로는 표현할 수 없어서 특수 기호(메타문자)가 필요하다.

| 하고 싶은 것 | 왜 평범한 글자로는 안 되나 |
|---|---|
| 줄의 **맨 앞**이 `#`으로 시작하는 줄만 제외 (뒤에 `#`이 있는 줄은 그대로 두고 싶음) | "포함"만으로는 위치를 지정할 수 없음 |
| 날짜처럼 **숫자가 여러 자리 반복**되는 패턴 제외 (`2026-07-16`, `2026-07-17`, ... 매번 다른 날짜) | 모든 날짜를 하나하나 다 입력할 수 없음 |
| `주소`, `Address`, `ADDRESS`처럼 **여러 단어 중 하나라도** 있으면 제외 | 평범한 텍스트로는 "또는"을 표현 못함 |

## 3. 자주 쓰는 기호 표 (이것만 알아도 충분)

| 기호 | 의미 | 예시 | 매칭되는 예 |
|---|---|---|---|
| `.` | 아무 글자 1개 | `a.c` | `abc`, `axc`, `a5c` |
| `*` | 바로 앞 글자가 0번 이상 반복 | `ab*c` | `ac`, `abc`, `abbbbc` |
| `+` | 바로 앞 글자가 1번 이상 반복 | `ab+c` | `abc`, `abbc` (단, `ac`는 매칭 안됨) |
| `?` | 바로 앞 글자가 0번 또는 1번 | `colou?r` | `color`, `colour` |
| `^` | **줄의 맨 앞** | `^#` | `#comment` (앞에 다른 글자 있으면 매칭 안됨) |
| `$` | **줄의 맨 끝** | `;$` | 줄이 `;`로 끝날 때만 |
| `\d` | 숫자 1개(0~9) | `\d\d\d\d` | `2026`, `0715` |
| `\s` | 공백 문자 1개(스페이스, 탭 등) | `a\sb` | `a b` |
| `[...]` | 대괄호 안 문자 중 아무거나 1개 | `[0-9A-Fa-f]` | 16진수 한 글자(`3`, `C`, `f` 등) |
| `{n}` | 바로 앞 패턴이 정확히 n번 반복 | `\d{4}` | 숫자 정확히 4자리 |
| `\|` | "또는"(둘 중 하나) | `주소\|Address` | `주소`가 있거나 `Address`가 있는 줄 |
| `(...)` | 괄호로 묶어서 우선순위/그룹 지정 | `(ab)+` | `ab`, `abab`, `ababab` |

> `\d`, `\s` 앞의 백슬래시(`\`)는 "다음 기호를 특수한 의미로 해석하라"는 표시다. 반대로 `.`이나 `(` 같은 특수 기호를 **글자 그대로** 찾고 싶으면 앞에 백슬래시를 붙여 `\.`, `\(`처럼 써야 한다(4번 항목 참고).

## 4. TextCompare 실전 예제

아래는 실제로 제외 필터에 입력할 만한 패턴과, 그게 무엇을 제외하는지 설명이다.

### 4.1. 특정 단어가 포함된 줄 제외 (정규식 지식 불필요)
```
TIMESTAMP
```
→ `TIMESTAMP`라는 글자가 어디에든 있는 줄은 전부 제외.

### 4.2. 줄 시작이 `#` 또는 `//`인 주석 줄 제외
```
^#
```
→ 줄의 **맨 앞**이 `#`인 줄만 제외(중간에 `#`이 있는 줄은 안 건드림).
```
^//
```
→ 줄의 맨 앞이 `//`인 주석 줄 제외.

### 4.3. 날짜/시각처럼 매번 값이 바뀌는 줄 제외
```
\d{4}-\d{2}-\d{2}
```
→ `2026-07-16`처럼 "숫자4자리-숫자2자리-숫자2자리" 형태가 있는 줄 전부 제외(날짜가 몇 년도든 상관없이 매칭).
```
\d{2}:\d{2}:\d{2}
```
→ `14:32:07`처럼 시:분:초 형태가 있는 줄 제외.

### 4.4. 특정 속성(attribute) 값만 다른 줄 제외 (XML/설정 파일)
예를 들어 `address="01D0"`처럼 16진수 주소 값이 버전마다 바뀌는데, 그 차이 자체는 무시하고 싶을 때:
```
address="[0-9A-Fa-f]+"
```
→ `address="..."` 안에 16진수(0-9, A-F, a-f)가 하나 이상 들어있는 부분을 찾는다. 이 경우가 바로 **"매치 부분만 제외" 모드**가 어울리는 상황이다 — 이 모드로 등록하면 줄은 화면에 남고 `address="..."` 구간만 비교에서 무시되어(회색 표시), 주소 값만 다른 줄이 "같음"으로 판정된다. 반면 "라인 전체 제외" 모드로 등록하면 그 줄 전체가 화면에서 사라지므로, 줄의 나머지 부분(다른 속성 등)의 차이까지 놓치게 된다.

### 4.5. 여러 단어 중 하나라도 있으면 제외
```
DEBUG|TRACE|VERBOSE
```
→ `DEBUG`, `TRACE`, `VERBOSE` 중 아무거나 하나라도 포함된 줄을 전부 제외.

### 4.6. 빈 줄(공백만 있는 줄 포함) 제외
```
^\s*$
```
→ 줄 시작(`^`)부터 끝(`$`)까지 공백 문자(`\s`)만 0번 이상(`*`) 있는 줄, 즉 완전히 빈 줄이나 공백만 있는 줄을 제외.

### 4.7. 대소문자 구분 없이 매칭하고 싶을 때
```
(?i)error
```
→ 맨 앞의 `(?i)`는 "이 패턴 전체를 대소문자 구분 없이 검사하라"는 표시. `error`, `Error`, `ERROR`, `Error` 모두 매칭된다.

> 참고: 비교 옵션에 있는 "대소문자 무시" 체크박스는 **좌/우 줄 내용이 같은지 비교할 때만** 적용되고, 제외 필터 패턴 자체의 대소문자 구분과는 별개다. 제외 필터에서 대소문자를 무시하려면 반드시 패턴 앞에 `(?i)`를 직접 붙여야 한다.

## 5. 자주 하는 실수

- **점(`.`)을 실제 마침표로 쓰고 싶은데 아무 글자나 매칭됨**: 파일 확장자처럼 `.tpml`을 찾고 싶으면 `.`이 아니라 `\.`로 써야 한다 (`config\.tpml`). 그냥 `.`을 쓰면 "아무 글자 + tpml"이 되어 `XtpmL` 같은 것도 우연히 매칭될 수 있다.
- **괄호, 대괄호를 실제 문자로 찾고 싶을 때**: `(`, `)`, `[`, `]`도 정규식에서 특수한 의미가 있으므로, 실제 괄호 문자를 찾으려면 `\(`, `\)`, `\[`, `\]`로 이스케이프해야 한다.
- **패턴이 잘못됐는데 왜 안 되는지 모르겠을 때**: 제외 필터 편집 창의 "상태" 칸에 그 패턴이 유효한지, 유효하지 않다면 정확히 어떤 오류인지(.NET 정규식 엔진이 알려주는 원문 메시지)가 바로 표시된다. 빨간 글씨로 뜨면 패턴에 문법 오류가 있다는 뜻이다.

## 6. 더 배우고 싶다면

- 온라인에서 정규식을 입력하면서 즉시 어느 부분이 매칭되는지 색으로 보여주는 도구들이 있다(예: regex101.com — ".NET" 엔진 옵션을 선택하면 TextCompare와 동일한 문법으로 테스트할 수 있다). 패턴이 복잡해질수록 이런 도구로 미리 확인해보고 붙여넣는 것을 권장한다.
- TextCompare의 제외 필터는 .NET(`System.Text.RegularExpressions.Regex`) 정규식 문법을 그대로 사용한다. 이 문서에서 다루지 않은 더 복잡한 문법(전방탐색, 캡처 그룹 이름 지정 등)이 필요하면 .NET 정규식 공식 문서를 참고한다.
