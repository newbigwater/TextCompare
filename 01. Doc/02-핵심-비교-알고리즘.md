# 핵심 비교 알고리즘

[[00-개요|← 개요로 돌아가기]]

## Myers O(ND) Diff (`TextCompare.Core.MyersDiff<T>`)

두 시퀀스 사이의 최단 편집 스크립트(Shortest Edit Script)를 계산하는 표준 Myers 알고리즘의 제네릭 구현이다. `IList<T>` 두 개와 `IEqualityComparer<T>`만 있으면 어떤 타입에도 재사용할 수 있으며, 실제로 이 프로젝트에서 세 곳에 그대로 재사용된다:

| 사용처 | T | 비교자 |
|---|---|---|
| 라인 비교 (`DiffDocument.Build`) | `string` (한 줄) | `LineHasher` (대소문자/공백 옵션 반영) |
| 문자 단위 강조 (`IntralineDiffer`) | `char` | 기본 비교자 |
| XML/JSON 자연 키 배열 매칭 (`KeyedListMatcher.MatchByKey`) | `string` (키 값) | 기본 비교자 |
| XML/JSON 위치 기반 폴백 매칭 (`KeyedListMatcher.MatchPositional`) | `StructuredNode` | `StructureEquality`(깊은 동등성) |

동작: 공통 prefix/suffix를 먼저 잘라내 탐색 범위를 최소화한 뒤, 전진 탐색(forward search) + trace 기록 + 역추적(backtrack)으로 편집 경로를 구하고, 연속된 삭제/삽입 편집을 `DiffChange` 블록으로 병합(coalesce)한다.

`DiffChange`는 `StartA/CountA`(좌측 구간), `StartB/CountB`(우측 구간)로 구성되며 `IsDelete`/`IsInsert`/`IsReplace`로 종류를 판별한다.

## ghost-line 정렬 — WinMerge 오정렬 문제의 해결책

### 문제

WinMerge류 라인 비교 도구는 삭제/삽입이 섞인 교체(replace) 블록을 **위치 기준으로 그대로 짝지어 나열**하는 경향이 있다. 예:

```
As-Is        To-Be
A            A
B      →     C
C            (없음)
```

B가 삭제된 것뿐인데, B와 C가 "같은 자리의 서로 다른 내용"처럼 잘못 나란히 표시되어 실제로는 무관한 두 줄이 비교되는 것처럼 보인다.

### 해결책 (`TextCompare.Alignment.DocumentAligner`)

`MyersDiff`가 계산한 `DiffChange` 목록을 순회하며, 교체 구간에서 **좌/우 개수가 다른 만큼 반대편에 ghost(빈 placeholder) 행을 삽입**한다:

```csharp
// 겹치는 부분(min(countA, countB))만 Changed 쌍으로 처리
for (int i = 0; i < paired; i++) { /* RowKind.Changed */ }
// 남은 삭제분은 LeftOnly + 우측 ghost
for (int i = paired; i < countA; i++) { /* RowKind.LeftOnly, RightLineNo=null */ }
// 남은 삽입분은 RightOnly + 좌측 ghost
for (int i = paired; i < countB; i++) { /* RowKind.RightOnly, LeftLineNo=null */ }
```

같은 예시(A,B,C vs A,C)를 정렬하면:

```
Left        Right
A     |     A        (Same)
B     |     (ghost)   (LeftOnly — B는 삭제됨, 우측엔 빈 줄)
C     |     C          (Same)
```

B와 C가 절대 같은 줄로 짝지어지지 않는다. `AlignedRow.IsLeftGhost`/`IsRightGhost`(`LeftLineNo`/`RightLineNo`가 `null`인지로 판정)로 화면에서 빈 줄로 렌더링된다.

> ghost 행은 **표시 전용**이다. 편집 모드에서 실제 저장되는 텍스트에는 절대 포함되지 않는다 — `DiffViewerControl`이 편집기용 텍스트를 만들 때는 ghost가 아닌 행만 걸러서(`GetRealRows`) 사용한다. [[04-UI-레이어#편집-모드]] 참고.

### `RowKind`

| 값 | 의미 |
|---|---|
| `Same` | 좌우 동일 |
| `Changed` | 좌우 모두 존재하지만 내용이 다름(치환) |
| `LeftOnly` | 좌측에만 존재(우측은 ghost) — 삭제 |
| `RightOnly` | 우측에만 존재(좌측은 ghost) — 삽입 |

## 정규화 옵션 (`DiffOptions` / `LineHasher`)

`LineHasher`는 `IEqualityComparer<string>`을 구현해 `MyersDiff<string>`에 그대로 주입된다. 비교 전 각 줄에 다음을 순서대로 적용:

1. `IgnoreTrailingWhitespace`(기본 true) — 줄 끝 공백 제거
2. `IgnoreWhitespace` — 연속 공백을 한 칸으로 축소(대소문자 무시 체크박스와 별개 옵션)
3. `IgnoreCase` — 대문자로 통일 후 비교

정규화는 **비교 판정에만** 사용되고, 화면에는 원문이 그대로 표시된다.

## 문자 단위 강조 (`TextCompare.Intraline.IntralineDiffer`)

`RowKind.Changed`로 판정된 좌/우 라인 쌍에 대해, 두 문자열을 `char` 시퀀스로 보고 다시 한 번 `MyersDiff<char>`를 실행해 실제로 다른 부분만 `CharSpan(Start, Length, IsDifferent)` 목록으로 반환한다. `DiffPaneControl`(메인 비교 뷰)과 `PreviewBarControl`(하단 미리보기, `DiffHighlighter.ApplyRowColors`를 통해)이 이를 사용해 변경된 줄 안에서도 실제로 달라진 글자만 진한 노란색으로 덧칠한다.
