# 빌드 및 테스트

[[00-개요|← 개요로 돌아가기]]

## 프로젝트 구성

- `TextCompare.sln`
  - `TextCompare.csproj` — 실행 파일 본체 (.NET Framework 4.8, WinExe, classic csproj)
  - `TextCompare.SelfTest.csproj` — 콘솔 기반 회귀 테스트 (UI 없이 로직만 검증)
- classic(비 SDK-style) csproj이므로 **새 파일을 추가하면 반드시 `<Compile Include>` 항목을 직접 추가**해야 한다(자동 glob 없음). UI가 아닌 로직 파일은 `TextCompare.SelfTest.csproj`에도 `<Link>`로 링크 추가.

## 빌드 방법 (CLI)

Visual Studio 2019/2022가 설치되어 있어야 하며, **`.NET Framework에 내장된 구버전 MSBuild.exe`(`C:\Windows\Microsoft.NET\Framework64\v4.0.30319\MSBuild.exe`)를 쓰면 안 된다** — 이 프로젝트의 `ToolsVersion="15.0"` 형식을 이해하지 못해 구형 컴파일러로 잘못 빌드된다. 반드시 Visual Studio에 포함된 MSBuild를 사용한다:

```powershell
# 설치 경로 확인 (vswhere)
& "C:\Program Files (x86)\Microsoft Visual Studio\Installer\vswhere.exe" -latest -products '*' -requires Microsoft.Component.MSBuild -property installationPath
```

```bash
# Git Bash에서 빌드 (MSYS 경로 변환이 /p: 인자를 깨뜨리므로 MSYS_NO_PATHCONV=1 필수)
cd "D:/50. Utility/Compare/03. Src/TextCompare"
MSYS_NO_PATHCONV=1 \
  "/c/Program Files (x86)/Microsoft Visual Studio/2019/Professional/MSBuild/Current/Bin/MSBuild.exe" \
  TextCompare.sln -p:Configuration=Debug -p:Platform="Any CPU" -nologo -v:minimal
```

> 머신 환경변수 `platform`(예: `C:\platform`)이 MSBuild의 `Platform` 속성과 충돌할 수 있으므로, CLI 빌드 시 `-p:Platform=` 을 항상 명시적으로 지정한다(환경변수 자체는 건드리지 않는다).

Visual Studio에서는 그냥 `TextCompare.sln`을 열고 빌드하면 된다.

## TextCompare.SelfTest — 회귀 테스트

UI 없이 순수 로직만 검증하는 콘솔 프로그램. `Program.cs` 안에 카테고리별 테스트 메서드가 있다:

| 카테고리 | 검증 대상 |
|---|---|
| `RunCoreTests` | `MyersDiff` 기본 동작(추가/삭제/치환/빈 시퀀스 등) |
| `RunAlignmentTests` | `DocumentAligner`의 ghost-line 정렬(핵심 시나리오: A,B,C vs A,C) |
| `RunIntralineAndDocumentTests` | 문자 단위 강조, `DiffDocument` 통계 |
| `RunEncodingTests` | `LineSplitter`, `EncodingDetector`(BOM/UTF-8/CP949) |
| `RunStructureParsingTests` | XML/JSON 파서 |
| `RunNodeKeyStrategyTests` | 자연 키 탐색 우선순위 |
| `RunKeyedListMatcherTests` | 키 기반/위치 기반 형제 매칭 |
| `RunPrettyPrinterTests` | XML/JSON 재직렬화 |
| `RunStructureDifferEndToEndTests` | XML/JSON 구조 비교 end-to-end (삭제/추가/id 재사용 시나리오 포함) |

총 35개 테스트. 실행:

```bash
cd "D:/50. Utility/Compare/03. Src/TextCompare"
MSYS_NO_PATHCONV=1 ./TextCompare.SelfTest/bin/Debug/TextCompare.SelfTest.exe
```

모두 통과하면 `ALL TESTS PASSED`를 출력하고 종료 코드 0을 반환한다.

## UI 변경 시 검증 원칙

이 프로젝트는 UI 자동화 테스트가 없으므로, WinForms 화면 변경 시 아래 순서로 수동/스크립트 검증한다:

1. 빌드 + SelfTest로 로직 회귀가 없는지 먼저 확인.
2. 화면 검증은 **전체 화면 스크린샷보다 `Control.DrawToBitmap()`(개별 컨트롤 단위)이 더 안정적**이다. 단, `RichTextBox`는 `DrawToBitmap`으로 내용이 비어 보이는 알려진 제약이 있으므로, 그 경우 텍스트/색상 속성을 리플렉션으로 직접 읽어 검증한다.
3. 실제 창을 캡처해야 한다면, 같은 스크립트 안에서 `Start-Process -PassThru`로 얻은 프로세스 핸들의 `GetWindowRect` 영역만 캡처한다(전체 화면 캡처 금지 — 다른 창의 민감한 정보가 찍힐 위험).
